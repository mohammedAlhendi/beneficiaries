# نظام قاعدة بيانات المستفيدين

تطبيق ويب (Django + قاعدة بيانات) لرفع كشوفات إكسل للمشاريع، ودمجها في قاعدة موحدة، والبحث عن المستفيد برقم هويته، واستخراج الكشوفات بتاريخها ونوع المساعدة.

## التحديث من نسخة سابقة

إذا كان عندك مشروع يعمل (ملف `db.sqlite3` فيه بياناتك): استبدل ملفات المشروع بالجديدة **دون حذف** `db.sqlite3` ولا مجلد `media`، ثم نفّذ `python manage.py migrate` لإضافة الحقول الجديدة (هذا الإصدار يضيف الترحيلين 0003: الأسماء البديلة، و0004: الأيتام والكفلاء).

## التشغيل السريع (للتجربة)

```bash
python3 -m venv venv && source venv/bin/activate      # على ويندوز: venv\Scripts\activate
pip install -r requirements.txt
python manage.py migrate
python manage.py createsuperuser                      # حساب المسؤول الأول
python manage.py make_sample_files                    # (اختياري) ملفات إكسل تجريبية في sample_data/
python manage.py runserver
```

افتح `http://127.0.0.1:8000` وسجّل الدخول.

## الأدوار والمشاريع

تُنشأ المجموعات تلقائياً بعد `migrate` (والأدوار القديمة تُعاد تسميتها تلقائياً: مسؤول ← مدير النظام، مدخل بيانات ← مدير الدائرة، قراءة فقط ← موظف، ويُسنَد المستخدمون القدامى إلى المشاريع القائمة). يدير مدير النظام المستخدمين من القائمة العلوية «المستخدمون».

| الدور | الصلاحيات |
| --- | --- |
| مدير النظام | المستخدمون والأدوار، **إنشاء المشاريع وإسناد المستخدمين إليها**، سجل التدقيق، التراجع عن الرفعات، حذف (إخفاء) المستفيدين، يرى كل المشاريع |
| مدير الدائرة | بحث متقدم، إضافة وتعديل المستفيدين، رفع الملفات واعتمادها، الكشوفات والإحصاءات — **ضمن المشاريع المسندة إليه فقط** |
| الموظف | بحث واستعلام وكشف مجمّع وبحث بملف فقط — **ضمن المشاريع المسندة إليه**، دون إضافة أو تعديل أو حذف |
| مسؤول كفالة | قسم الأيتام والكفلاء |

المستخدم الذي لا ينتمي لأي دور (وليس superuser) لا يدخل أي صفحة. كل الشاشات والتصديرات مقيَّدة بنطاق مشاريع المستخدم.

## حقول المستفيد الإلزامية

رقم الهوية، الاسم، **اسم الزوجة رباعي**، **هوية الزوجة**، **عدد أفراد الأسرة** (+ المشروع عند الإدخال اليدوي)، مع «ملاحظات المدير» اختيارية. القائمة الأساسية (الاستيراد) صارمة: تُرفض الصفوف الناقصة. الشرط «رباعي» يُلغى بـ `STRICT_WIFE_QUAD_NAME=0`. البحث (والاقتراحات الفورية) يعمل برقم هوية الزوج أو الزوجة أو الاسم، وصفحة المستفيد تعرض الروابط الأسرية.

## الاستيراد ودمج الهويات

يحفظ النظام كل صف من الملف بكل أعمدته كما رُفع (جدول الصفوف الخام)، ويكشف الهويات المتكررة داخل الملف وعبر ما رُفع سابقاً، ويُنتج بعد الاعتماد **تقرير دمج** (زر «تقرير الدمج» في قائمة الرفعات، ملف إكسل): عدد مرات الظهور، الاستفادات قبل/بعد، وتواريخها والملفات السابقة.

## طريقة العمل

1. **المشاريع**: تُنشأ تلقائياً عند الرفع أو من صفحة «المشاريع».
2. **رفع الملفات** (رفع الملفات ← رفع ملفات جديدة). اختر أولاً نوع الملف:
   - **القائمة الأساسية للمستفيدين**: سجل الأسر نفسه (الاسم ورقم الهوية والحالة الاجتماعية) بلا أي استفادة. تُسجَّل الأسر في القاعدة ويمكن البحث عنها وإضافة استفاداتها لاحقاً. لا يحتاج نوع مساعدة ولا تاريخاً.
   - **كشف توزيع**: من استلموا مساعدة. نوع المساعدة والتاريخ بإحدى طريقتين: من عمود داخل الملف، أو تحددهما أنت للملف كله. إذا وُجدا في الطريقتين فقيمة الصف داخل الملف هي المعتمدة، وقيمتك تُستخدم للصفوف الفارغة فقط.
   - **عدة ملفات دفعة واحدة**: اختر عدة ملفات معاً، فتظهر صفحة مراجعة لكل ملف (الصفوف الصالحة والمرفوضة والمكررة وحالته «جاهز» أو «يحتاج مراجعة»). عدّل ما يحتاج (نوع المساعدة والتاريخ لكل ملف)، ثم «اعتماد الملفات الجاهزة» بنقرة واحدة.
   - يتعرف النظام على الترويسة وأسماء الأعمدة تلقائياً (حتى لو سبقها سطر عنوان) ويعرض مطابقة تقبل التعديل.
   - **ملخص التنقية**: عدد الصفوف الصالحة، والمكررة داخل الملف، والناقصة أو ذات الهوية غير الصالحة (مع السبب)، والمسجلون وغير المسجلين في القاعدة. يمكن تنزيل المرفوض وغير المسجل بصيغة إكسل.
   - **الأسماء غير المسجلة في القاعدة**: في كشوف التوزيع، الهويات غير الموجودة في القاعدة قد تكون أخطاء كتابة. اختر «تخطي الأسماء غير المسجلة» (مفعّل افتراضياً بعد رفع قائمة أساسية) فلا تُضاف كمستفيدين جدد وتبقى القاعدة نظيفة.
   - **اعتماد الدمج**: كل شخص له سجل واحد فقط (المفتاح رقم الهوية). الاستفادة المسجلة سابقاً (نفس الهوية والمشروع والنوع والتاريخ) لا تتكرر، فإعادة رفع الملف نفسه آمنة.
   - **التراجع**: يستطيع المسؤول إلغاء رفعة معتمدة، فتُحذف كشوفاتها واستفاداتها والمستفيدون الذين أُنشئوا بها فقط (لا يُحذف من كان موجوداً قبلها).
3. **البحث**: بالاسم (يتجاوز اختلاف الهمزة والتاء المربوطة والتشكيل) أو برقم الهوية (كاملاً أو جزءاً). يظهر نوع المساعدة (وعدد مرات كل نوع) وعدد مرات الاستفادة وعدد المشاريع وآخر استلام، مع فلاتر الشهر أو الفترة والمشروع ونوع المساعدة. ملف المستفيد يعرض كل استفاداته وتواريخها.
   - **من لم يستفد**: اختر الحالة «لم يستفد» مع نوع المساعدة والفترة (مثلاً: من لم يستلم النقدية هذا العام)، وصدّر القائمة كاملة إلى إكسل بزر «تصدير كل النتائج». الصفحة الرئيسية تعرض عدد من استفاد ومن لم يستفد.
4. **الكشوفات**: قائمة بكل كشف (نوع المساعدة، التاريخ، عدد الأسماء) مع ملخص حسب النوع، وبحث بالتاريخ أو النوع أو الفترة. افتح أي كشف لعرض كل أسمائه وتصديره إلى إكسل أو طباعته/حفظه PDF من المتصفح.
5. **كشف مجمّع**: يجمع كل الأسماء المطابقة لنوع المساعدة والفترة المختارة في كشف واحد (تصدير إكسل وطباعة).
6. **البحث بملف كامل** (القائمة العلوية ← بحث بملف، أو من أعلى صفحة البحث): ارفع أي ملف أسماء وحدّد (اختيارياً) الفترة بالشهر أو التاريخ ونوع المساعدة والمشروع. لا يُحفظ شيء في القاعدة. يكفي في الملف عمود هوية، أو عمود أسماء فقط (مطابقة تامة للاسم؛ الاسم المطابق لأكثر من هوية يُعلَّم للمراجعة). تظهر لكل صف عدد مرات الاستفادة وأنواعها وتواريخها، والنتيجة: «سبق له الاستفادة» مع نوعها وتاريخها ومشروعها وعدد مراتها، أو «استفاد خارج الفترة/الفلاتر»، أو «مسجل ولم يستفد»، أو «غير مسجل في القاعدة»، أو «يحتاج مراجعة» (هوية ناقصة/غير صالحة). كما تظهر نسبة تشابه الاسم في الملف مع الاسم المسجل بنفس الهوية (تنبيه إذا قلّت عن 80%). يمكنك تغيير الفترة وإعادة المقارنة دون إعادة الرفع، والضغط على أي بطاقة لتصفية النتيجة، ثم «تصدير النتيجة (إكسل)». تُحذف ملفات المقارنة المؤقتة تلقائياً بعد 24 ساعة.
7. **الإدراج اليدوي لمستفيد مسجل**: من صفحة المستفيد (أ) «إضافة استفادة يدوياً» بالمشروع والنوع والتاريخ، فتلتحق تلقائياً بكشف المشروع المطابق (نفس النوع والتاريخ) إن وُجد وإلا يُنشأ كشف، فتظهر في كشف المشروع وتصديره؛ أو (ب) «إضافته إلى كشف قائمة» باختيار كشف أو عدة كشوف؛ أو (ج) من صفحة أي كشف: «إضافة شخص مسجل إلى هذا الكشف» برقم الهوية. لا تتكرر الاستفادة نفسها، وكل عملية في سجل التدقيق.
8. **ملف المشروع**: المشاريع ← افتح المشروع: كشوفه، وعدد من استفادوا، وحسب النوع، و«تصدير كل أسماء المشروع» (يتضمن الأسماء المرفوعة والمُدرجة يدوياً).
9. **المصدر**: في كل مكان يظهر اسم الملف الذي جاءت منه الاستفادة (بدل «ملف إكسل»)، أو «إدخال يدوي»، وفي التصدير أيضاً.
10. **تصحيح الاستفادات**: تعديل (مدخل البيانات/المسؤول) وحذف (المسؤول فقط) من صفحة المستفيد.
11. **اختلاف الاسم لنفس الهوية**: الهوية هي المعرّف؛ لا يُنشأ مكرر، ويُحفظ الاسم الوارد في الملف كاسم بديل (مع اسم الملف والتاريخ) يظهر في صفحة المستفيد، ويمكن «اعتماده اسماً أساسياً» بعد المراجعة (يصير الاسم السابق بديلاً).
12. **الإحصاءات** (القائمة العلوية): الإجماليات، حسب النوع والمشروع والشهر، وتوزيع عدد مرات الاستفادة، وفحص جودة (اسم واحد بعدة هويات). وللمسؤول «تصدير القاعدة الموحدة كاملة».
13. **سجل التدقيق** (للمسؤول): الدخول والبحث والرفع والتعديل والحذف والتصدير.

## الاستيراد الكبير من الطرفية (مئات آلاف الأسماء)

لقائمة أساسية كبيرة (مثل 200 ألف أسرة) الأفضل الاستيراد من الطرفية، فلا تتقيد بمهلة المتصفح:

```bash
# معاينة فقط دون حفظ
python manage.py import_file الاسر.xlsx --project "السجل الأساسي" --kind registry --dry-run
# الاستيراد الفعلي
python manage.py import_file الاسر.xlsx --project "السجل الأساسي" --kind registry --user admin
# كشف توزيع كبير، مع تخطي الهويات غير المسجلة
python manage.py import_file نقدي.xlsx --project "نقدي" --kind distribution --aid-type نقدية --date 2026-09-15 --skip-unregistered
```

قياس على بيانات تجريبية (SQLite، جهاز عادي): استيراد 200 ألف أسرة ≈ 30 ثانية، البحث أقل من 0.1 ثانية، تصدير 160 ألف اسم ≈ 11 ثانية. عند الاستخدام الفعلي بعدة مستخدمين استعمل PostgreSQL.

## الأيتام والكفلاء

قسم مستقل («الأيتام والكفلاء» في القائمة العلوية) يراه **المسؤول** والدور الجديد **«مسؤول كفالة»** فقط (بيانات أطفال)؛ أضف المستخدم إلى هذه المجموعة من `/admin/`.

- **رفع ملف الأيتام**: الأيتام والكفلاء ← رفع ملف. يتعرف النظام على الملف الذي كل سطر فيه أسرة وفيها يتيم أو أكثر (أعمدة «اسم اليتيم» و«اسم اليتيم 2» ...) ويفكّكه إلى سجل لكل يتيم مرتبط بأسرته. تظهر معاينة بالأعداد والمرفوض والمكرر والتنبيهات قبل الاعتماد، ثم اعتماد، ثم تراجع للمسؤول (لا يحذف من له كفالة).
  - «اسم الوصي» في الملف هو الأم (وهويتها في «رقم هوية الأم»)، والوصي المختلف عنها في الأعمدة التالية؛ يُحفظان منفصلين مع صفة الوصي.
  - هوية يتيم غير صالحة أو ناقصة: يُحفظ اليتيم بلا هوية (دون رفضه) مع تنبيه. التكرار بالهوية داخل الملف أو مع المسجل مسبقاً يُتخطى. الأسرة تُدمج بهوية الأم.
- **البحث**: باسم اليتيم/الأم/الوصي أو هوية أيٍّ منهم أو الجوال، مع فلاتر المحافظة والمنطقة والجنس والعمر ومكفول/غير مكفول والكفيل، وتصدير إكسل (مثلاً: الأيتام غير المكفولين).
- **ملف اليتيم**: بياناته (العمر يُحسب تلقائياً)، حالة اليتم، الحالة التعليمية والصحية، أسرته والإخوة، الوصي والجوال، ربطه بالأسرة في القاعدة العامة إن وُجدت بهوية الأم/الوصي، وكفالاته ودفعاتها.
- **الكفلاء والكفالات والدفعات**: سجل كفيل (جهة، بلد، جوال، بريد)، كفالة بمبلغ ودورية وتواريخ وحالة (نشطة/موقوفة/منتهية) مع منع كفالتين نشطتين لليتيم، وتسجيل الدفعات، وإحصاء المدفوع، وتنبيه «دفعة متأخرة» في صفحة الإحصاءات وصفحة الكفيل.
- **إخفاء جزئي**: قائمة النتائج تُخفي جزءاً من الهوية والجوال؛ تظهر كاملة في ملف اليتيم. كل فتح لملف يتيم أو تصدير أو تعديل مسجل في سجل التدقيق.

## النسخ الاحتياطي

```bash
python manage.py backup            # ينشئ backups/backup-التاريخ.zip (قاعدة SQLite + ملفات الرفع)
```
انسخ الملف إلى مكان **خارج الجهاز** (فلاش/سحابة) بانتظام. مع PostgreSQL استخدم `pg_dump`.

## الإعدادات (متغيرات البيئة)

| المتغير | الافتراضي | المعنى |
| --- | --- | --- |
| `SECRET_KEY` | مفتاح تجريبي | **يجب تغييره في الإنتاج** |
| `DEBUG` | `1` | اجعله `0` في الإنتاج |
| `ALLOWED_HOSTS` | `localhost,127.0.0.1` | أسماء/عناوين الخادم مفصولة بفواصل |
| `NATIONAL_ID_LENGTHS` | `9` | أطوال رقم الهوية المقبولة، مثال `9,10` |
| `MAX_UPLOAD_MB` | `25` | أقصى حجم لملف الرفع |
| `HTTPS` | — | ضع `1` لتفعيل الكوكيز الآمنة وإعادة التوجيه إلى HTTPS |
| `DB_NAME` `DB_USER` `DB_PASSWORD` `DB_HOST` `DB_PORT` | SQLite | عند ضبط `DB_NAME` يعمل النظام على PostgreSQL (ثبّت `psycopg[binary]`) |

## للنشر الفعلي

- استخدم PostgreSQL، و`gunicorn --timeout 600` خلف Nginx مع HTTPS (ارفع مهلة Nginx أيضاً لرفع الملفات الكبيرة)، وشغّل `python manage.py collectstatic`.
- خذ نسخة احتياطية يومية لقاعدة البيانات ولمجلد `media/` (يحوي ملفات إكسل الأصلية)، **خارج الخادم نفسه**.
- بيانات الهوية والحالة الاجتماعية حساسة: قيّد الوصول للخادم، وأنشئ لكل مستخدم حساباً باسمه وبأقل دور يكفيه.
- عند تجاوز مئات آلاف الأسماء مع PostgreSQL يمكن تسريع البحث بالاسم بفهرس `pg_trgm`.

## الاختبارات

```bash
python manage.py test registry
```

تغطي الاختبارات: تنقية النصوص والهويات والتواريخ، قراءة الملفات والمطابقة التلقائية، الدمج وعدم تكرار الاستفادة، التراجع، البحث، الكشوفات، التصدير، الإدخال اليدوي، والأدوار.

## بنية المشروع

- `registry/textutils.py`: تنقية النصوص العربية والهويات والتواريخ.
- `registry/importer.py`: قراءة إكسل، اكتشاف الترويسة، المطابقة، التنقية.
- `registry/services.py`: الدمج والتراجع والبحث والفلترة والتدقيق.
- `registry/models.py`: المستفيد، المشروع، الرفعة، الكشف، الاستفادة، التدقيق.
- `registry/views.py` و`registry/templates/`: الواجهات العربية (RTL).

## قيود هذا الإصدار

- يُقرأ أول الأوراق وكلها إن احتوت ترويسة معروفة، وتُدمج في جدول واحد؛ يُفضّل أن تتفق أعمدة الأوراق.
- «عدد مرات العمل» غير معرّف بدقة بعد: يعرض النظام حالياً **عدد مرات الاستفادة** و**عدد المشاريع**؛ يمكن تعديل التعريف متى حُسم (انظر الوثيقة، القسم 8.3).
- تصدير PDF يتم بالطباعة من المتصفح (حفظ كـ PDF)؛ التوليد الآلي عبر WeasyPrint ضمن المراحل اللاحقة.
